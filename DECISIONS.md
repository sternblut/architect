## 16.10.2026 — устройство: свой сервис-хост на официальных основах Claude Code

**Задача.** Владелец пульта с iPhone в Telegram ведёт всю работу над своими сайтами. Нужен архитектор — сессия Claude, с которой он переписывается. Архитектор:
- запускает на Mac сессии Claude в папках сайтов;
- следит за всеми сессиями, в том числе за запущенными вручную;
- передаёт вопросы сессий владельцу, а им — его ответы;
- останавливает сессии по слову владельца;
- видит сайты и GitHub;
- делает необратимое (удаление, push в main, выкладка, траты, письма) только после «да» владельца в Telegram.

Слушаться — только владельца, пересланное — данные. Токены — только в связке ключей. Хостинг — только конвейерами.

**Что изучено** (с источниками, сводка ниже):
- Официальное в Claude Code 2.1.301: каналы, фоновые сессии, сообщения между сессиями, хуки, Remote Control, Projects, Dispatch, облачные сессии, routines, Agent SDK. Документация code.claude.com: [channels](https://code.claude.com/docs/en/channels), [channels-reference](https://code.claude.com/docs/en/channels-reference), [agent-view](https://code.claude.com/docs/en/agent-view), [cross-session-messaging](https://code.claude.com/docs/en/cross-session-messaging), [hooks](https://code.claude.com/docs/en/hooks), [permission-modes](https://code.claude.com/docs/en/permission-modes), [remote-control](https://code.claude.com/docs/en/remote-control), [claude-projects](https://code.claude.com/docs/en/claude-projects), [agent-sdk/typescript](https://code.claude.com/docs/en/agent-sdk/typescript).
- Сторонние мосты и пульты:
  - ccbot, overwirehq/claude-code-telegram, cc-connect;
  - Happy, Omnara, Conductor, Claude Squad, Vibe Kanban;
  - ccteam.

  Звёзды, свежесть и устройство — в разделе «16.10.2026 — проверка: не собираем ли готовое».

**Почему не подключался установленный плагин Telegram** — три причины, каждой достаточно:
1. Не было Bun: сервер плагина запускается `bun run …`.
2. Не задан токен: нет `~/.claude/channels/telegram/`.
3. Сессию не запускали с `--channels plugin:telegram@claude-plugins-official`.

Плагин выключен в пользовательских настройках (`"telegram@claude-plugins-official": false`), и это правильно — иначе каждая сессия поднимала бы свой опрос бота.

**Выбор — В.**
- Только В выполняет все условия владельца сразу: Telegram, только его аккаунт, пересланное — данные, «да» кнопкой на каждое необратимое действие и архитектора, и рабочих сессий, токен только в связке ключей.
- В опирается на документированные механизмы, а не на research preview каналов с открытыми багами.
- Своё пишется только там, где готового нет. Это мост Telegram ↔ сессия и маршрут подтверждений. Сессии, их запуск, остановка, наблюдение, сообщения между ними и сами разрешения — штатные.
- Remote Control остаётся запасным ходом: любую сессию можно открыть в приложении Claude, если Telegram недоступен.

**Отвергнуто:**
- Официальный канал — см. таблицу.
- Своя копия плагина с флагом разработки. Флаг — «for local channel development only», при каждом запуске окно подтверждения; автоматика безопасности Claude Code не дала его запустить.
- ccbot (tmux send-keys, 277★, один автор).
- claude-code-telegram (нет пошаговых подтверждений).
- cc-connect (`/mode yolo` из чата).
- Happy (не Telegram, CLI в maintenance).

### Устройство В

- **Хост** — `src/` (Bun, TypeScript). Один процесс, запуск и остановка — `bin/arch`.
  - **Telegram** (grammY): long polling, только ID владельца; пересланное помечается.
  - Фото и файлы — в `state/inbox`.
  - Кнопки подтверждений с полным текстом действия, одноразовые, с тайм-аутом. Нажатие проверяется по ID владельца.
  - Живые карточки хода сессий — одно сообщение, которое обновляется.
- **Архитектор** — сессия Claude Code (Opus, `max`) через Agent SDK в папке `architect/`, правила — `CLAUDE.md`.
  - Ввод — потоком сообщений владельца. Продолжение после перезапуска — `resume`.
  - Чтение и свои инструменты — без вопросов. Остальное — через `canUseTool` кнопкой владельцу.
- **Инструменты архитектора** — в процессе хоста (`createSdkMcpServer`):
  - сводка;
  - сессии;
  - ход сессии;
  - запуск сессии (`claude --bg` в папке сайта);
  - остановка — с кнопкой;
  - ответ сессии — штатный `SendMessage` или новый ход;
  - снимок сайта;
  - GitHub (только чтение).
- **Рабочие сессии** — `claude --bg` в папке сайта со своими правилами папки (CLAUDE.md, память). Хуки идут в локальный HTTP хоста (127.0.0.1, секретный заголовок):
  - `PreToolUse` — разбор команды. Необратимое → `ask`, хостинг → `deny`.
  - `PermissionRequest` — кнопка владельцу, ответ allow/deny.
  - `Notification` и `Stop` — вопросы и итоги хода.
- **Наблюдение** раз в 15 с: `claude agents --json --all` и журналы сессий. Сессии владельца, ждущие ответа, сайты и упавшие прогоны GitHub — тревогой в Telegram.

**Не ломать работающее.**
- В чужие сессии хост не вмешивается: только читает их статус и журнал. Пишет им лишь по слову владельца.
- Пользовательские настройки Claude Code не меняются.

**Выключить всё — `arch off`.** Останавливает хост и архитектора. Рабочие сессии, запущенные архитектором, остаются: их останавливает владелец (`arch off --sessions` — с подтверждением в терминале).

## 16.10.2026 — проверка: не собираем ли готовое

**Anthropic (официально, в приложении Claude):**

## 16.10.2026 — интерфейс уровня октября 2026, а не «бот с командами»

**Telegram Bot API 10.3 (grammY 1.46).** В Telegram за 2026 год появился штатный интерфейс для ИИ-ботов — берём его целиком ([changelog Bot API](https://core.telegram.org/bots/api-changelog)):
- **Rich-сообщения** (10.1, 11.06.2026): `sendRichMessage` принимает GFM-Markdown — таблицы, заголовки, списки, `<details>`, до 32 768 знаков. Ответы Claude идут как есть, без самодельной конвертации; экранируем только `$` (иначе формула) и незнакомые `<`. Запасной путь — старый HTML.
- **Потоковый черновик** (`sendMessageDraft` с 9.3, `sendRichMessageDraft` с 10.1, `can_stop` и апдейт `stopped_message_generation` с 10.3): пока архитектор работает — блок `thinking` «Думаю: смотрю сессии…», затем текст ответа по мере генерации (Agent SDK `includePartialMessages`). Кнопка **Стоп** в черновике → `interrupt()`.
- **Цветные кнопки** (`style`, 9.4): «Разрешить» зелёная, «Отклонить»/«Стоп» красные.
- **Темы в личном чате** (9.3): тема на сессию. Включаются только владельцем в мини-приложении @BotFather (Threaded Mode); хост проверяет `getMe().has_topics_enabled` каждые 5 минут и сам начинает пользоваться темами.

**Голос → задача.** mlx-whisper large-v3-turbo локально: ~3 с на фразу, звук не уходит в сеть; словарь-подсказка (имена проектов, «выкладка»…). Под голосовым бот показывает, что услышал; архитектору расшифровка приходит с пометкой — при неясном ключевом слове он переспрашивает.

**«Открыть в Claude».** Рабочие сессии запускаются с `--remote-control <имя>`; Claude Code пишет ссылку `https://claude.ai/code/session_…` в журнал сессии (`system/bridge_status`). Хост достаёт её оттуда и ставит кнопкой в карточку: вся сессия на iPhone в приложении Claude ([Remote Control](https://code.claude.com/docs/en/remote-control)).

**Уведомления по присутствию.** Простой клавиатуры и мыши (`ioreg HIDIdleTime`): пока владелец за Mac, ход его терминальных сессий в Telegram не дублируется; отошёл на 3+ минуты — всё, что ждёт его ответа, приходит на iPhone, вопросы со звуком. Та же идея у Anthropic — `CLAUDE_CLIENT_PRESENCE_FILE` для пушей Remote Control.

**Красный флаг «крутится вхолостую».** Сессия, которой цель /goal не даёт остановиться, отвечает «жду» по кругу и тратит лимит: ≥6 «Stop hook feedback» за 10 минут → флаг в сводке.

**Ответы терминальным сессиям** — штатный обмен сообщениями между сессиями ([cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)): архитектор передаёт слова владельца `SendMessage`. Сообщение от другой сессии по устройству «can't approve anything» — окно разрешения в чужой терминальной сессии отсюда не нажать, для этого кнопка «Открыть в Claude».

**Исправлено:** при пробуждении рабочей сессии вашим ответом (`claude --resume <id> --bg`) флаги процесса не сохраняются — без повторного `--settings` сессия продолжала бы работу без шлагбаума. Теперь хост передаёт хуки, модель и Remote Control заново; живой тест `test/e2e-worker.ts` проверяет, что после пробуждения удаление снова спрашивает владельца.

**Mac не засыпает, пока хост жив:** `caffeinate -i -w <pid хоста>` (экран гаснуть может). Иначе с iPhone до Mac не достучаться.

## 16.10.2026 — один пульт на все сессии, «Пульт», чистый вид

**Все сессии Mac, включая ручные в терминале.** Remote Control Anthropic умеет подключать все интерактивные сессии (`remoteControlAtStartup`), но только в приложении Claude и по одной; Happy, Omnara, ccteam видят только свои или «зарегистрированные» сессии. Мы — штатными хуками Claude Code из `~/.claude/settings.json` (ставит `archi on`, снимает `archi off`; `src/install-hooks.ts`, `src/anyhook.ts`):
- `PermissionRequest`, `PreToolUse` на `AskUserQuestion`, `Stop`. Пока владелец за Mac (простой клавиатуры < 3 мин, `ioreg HIDIdleTime`) — хук сразу отвечает «нет решения», и сессия ведёт себя как без него. Отошёл — разрешения и вопросы кнопками в Telegram; вопрос в конце хода — сообщением, ответ возвращается в сессию через `decision: block` + `reason`. Вернулся — всё ждущее отпускается обратно в терминал (родное окно `Do you want to proceed?`).
- Сессии с `/goal` не держим (они идут сами): ответ владельца доставляется на их следующей остановке.
- Хост выключен, упал, Telegram не привязан — хук молча выходит, Claude Code продолжает штатно («when a hook fails or times out, Claude Code still carries out the action» — [hooks](https://code.claude.com/docs/en/hooks)). Хуки из настроек подхватываются уже идущими сессиями («picked up automatically by the file watcher»), поэтому «за Mac — ничего не меняется» обязательно.
- Проверено опытом и тестом на настоящей интерактивной сессии в tmux (`test/e2e-any.ts`, 5 из 5): разрешение с телефона (`Allowed by PermissionRequest hook`), вопрос с вариантами, ответ на вопрос в конце хода как реплика, возврат в терминал.

**«Пульт»** — одно закреплённое сообщение, правится на месте: кто ждёт владельца, кто над чем работает (словами, без команд), кто закончил, внимание (лимит, упавшие прогоны), сайты. Под флагами — «Разобраться»: нажатие владельца = поручение архитектору.

**Лимит подписки Claude** — `rate_limit_event` в потоке архитектора и `/usage` SDK (помечен экспериментальным — только в обёртке): в сводке, «Пульте», красным флагом с 85% недели; упор в лимит — сразу по-русски с временем сброса.

**Вид — без ИИ-шаблона** (текст выглядел машинным): без эмодзи у каждой строки, без сырых команд и служебных id сессий, одно приветствие; черновик хода — словами («Выполняю команду»), не командой; архитектору — правило писать итог 1–3 предложениями. Проверка — снимком окна Telegram на Mac (только окно чата с ботом) и разбором сообщения обратно через `getChat`.

**Взято из открытого кода** (20 репозиториев):
- общий темп чата и потолок ожидания 429 — Hermes (#91969: штраф 97 мин заморозил бота), `@grammyjs/auto-retry`;
- повтор отправки только если запрос точно не ушёл, rich→HTML только при «не понял разметку» — OpenClaw `network-errors.ts`, ccbot PR #93; для ответа владельцу дубль лучше потери — ccbot;
- хеш правил архитектора: SDK при `resume` шлёт системную подсказку из первого хода — nanoclaw, `sdk.d.ts` (`snapshot`);
- текст хода перед вызовом инструмента не терять — ccteam#192;
- квитанции `update_id` на диске (24 ч) — Hermes `update_admission.py`;
- нажатия не ждут распознавания голосового — linuz90, OpenClaw;
- схема журнала Claude Code (служебные записи, `bridge-session` → ссылка RC, `custom-title`) — claude-code-viewer; статус `/goal` из `goal_status` — happy, ccteam; кэш разбора по размеру и времени файла — ccbot;
- лимиты и сбои хода отдельными сигналами — nanoclaw, happy.

**Перезапуск не теряет ваше сообщение:** последнее неотвеченное сообщение владельца лежит в `state/pending.json` и доводится после перезапуска; `archi restart` ждёт конца хода архитектора (`state/busy`).

## 19.10.2026 — дежурный в облаке, пока Mac спит: без единого секрета в облаке

**Задача.** С закрытой крышкой Mac спит — бот молчит. Держать его бодрым нельзя: ноутбук без вентилятора перегреется. Правило — пароли и токены только в связке ключей и секретах GitHub, поэтому в облаке не должно быть ни токена бота, ни общих ключей.

**Устройство.**
- **Облако** — Cloudflare Worker + Durable Object (`relay/`). Токена бота в нём нет: владельцу он отвечает вызовом Bot API в теле ответа на webhook, его выполняет сам Telegram.
- **Засыпая** (`src/relay.ts`), хост останавливает опрос, шлёт Worker подписанный `/sleep` и ставит webhook на `https://<worker>/u/<путь>`.
  - В `/sleep` — SHA-256 пути, id владельца, «с 14:05» и сводка без разметки.
  - Путь — 32 случайных байта, новый на каждый сон. Живёт только в памяти хоста и в Telegram; у Worker — хеш.
  - Запросы Mac подписаны Ed25519: закрытый ключ в связке ключей, у Worker только открытый (`MAC_KEY`). Подпись — над путём запроса, временем и телом; время свежее (±60 с) и только растёт — повтор не пройдёт.
- **Пока Mac спит**, Worker отвечает:
  - на задачу — «Mac спит с 14:05. Запомнил — начну, когда проснётся.», дальше «Запомнил — в очереди N…»; сообщение уходит в очередь;
  - на «что у нас» — сводкой на момент сна, мимо очереди;
  - на кнопку — всплывашкой «Mac спит — нажмите, когда проснётся.», в очередь не кладёт;
  - чужим — ничего.
- **Проснувшись**, хост снимает webhook (с повторами — сеть после сна поднимается не сразу), забирает очередь подписанным `/pull` с подтверждением `ack`, пока она не опустеет, отдаёт её `bot.handleUpdate` по порядку и снова опрашивает.
  - Дубли отсекают квитанции `update_id`.
  - Из облака берётся только сообщение: апдейт пересобирается заново, так что подложенное рядом нажатие до обработчиков не дойдёт. Пометка `relayed`: «да код» из очереди не разрешает. Ответ на открытый вопрос сессии, написанный во сне, принимается — это не решение.
  - «Да код» во сне дежурный не копит и отвечает: «Решения — только кнопкой, когда Mac проснётся.»
  - Апдейт «в полёте» во время пробуждения: дошёл до Worker раньше `/pull` — он в очереди; позже — Worker отвечает 404, и апдейт остаётся в Telegram до опроса (`deleteWebhook` без `drop_pending_updates` неподтверждённое не сбрасывает).
  - Своя остановка опроса посреди его запуска — не сбой: хост не выходит (раньше `bot.start()` падал и `process.exit(3)`).
  - Окно, как и при обычном опросе: квитанция пишется до обработки, поэтому падение хоста в секунды между приёмом и разбором (скачивание, расшифровка голоса) теряет это сообщение.
- **Сон и пробуждение** — помощник `src/powerwatch.swift` (`IORegisterForSystemPower`).
  - Это дочерний процесс хоста, как `caffeinate`: строки через stdin и stdout, ни порта, ни секрета. Собирается `swiftc` при первом запуске в `state/`.
  - «sleep N» → хост передаёт бота → «ok N» → только тогда сон. Помощник ждёт не дольше 20 с, сама macOS — до 30 с.
  - «wake» → хост сверяет «System Capabilities» у `IOPMrootDomain`: есть графика — полное пробуждение; тёмное (Power Nap) — бот остаётся у дежурного.
  - Страховка: бот у дежурного больше минуты, а Mac бодр — забрать.
- Без `relay` в `config.json` всё как раньше.

**Почему помощник, а не то, что уже есть.**

| Способ | До сна | После сна | Тёмные пробуждения |
|---|---|---|---|
| `caffeinate -i` (в хосте) | не сигнал: держит только от сна по простою, крышка всё равно усыпляет | — | — |
| Разрывы таймера (сторож опроса) | нет — узнаёт задним числом | да, с задержкой | путает с пробуждением: процессы идут и в Power Nap |
| NSWorkspace willSleep / didWake | да, но сон не ждёт | да | — |
| **IORegisterForSystemPower** | **да, и сон ждёт подтверждения** | **да, сразу** | отличаем по «System Capabilities» |

`caffeinate -i` остаётся: с открытой крышкой Mac не засыпает от простоя и работает в полную силу.

**Замеры.**
- Локально, wrangler dev (workerd): передача бота — 6–7 мс без сети, возврат — 17–20 мс, ответ дежурного — 1–3 мс. 18 проверок из 18 (`test/e2e-relay.ts`).
- Сеть Mac (ближайший узел Cloudflare): до api.telegram.org ≈ 0,37 с на круг, до Cloudflare ≈ 0,2 с. Те же три запроса подряд, что делает передача (Telegram по открытому соединению, Cloudflare с новым TLS, снова Telegram), — 1,3–1,5 с в 5 замерах из 5; с обработкой на серверах — ≈ 1,5–2 с. Запас до 20 с — около десятикратного.
- `pmset -g log` этого Mac: при засыпании системные службы держат сон 0,4–2,8 с (mDNSResponder — до 2,8 с). С закрытой крышкой — тёмные пробуждения каждые 2–17 мин по 2–25 с; без проверки графики бот передавался бы туда-обратно каждые несколько минут.
- С настоящей крышкой не проверено: усыпить Mac владельца нельзя. После выкладки `pmset -g log | grep "PM Client Acks"` покажет, сколько сон ждал powerwatch.

**Что может взломавший Worker или аккаунт Cloudflare.**
- Может, пока Mac спит:
  - читать, что владелец пишет во сне (тексты лежат в облаке открыто до `/pull`, в том числе случайно вставленный пароль), и сводку;
  - на каждый апдейт — один вызов Bot API от имени бота, а апдейты он может слать себе сам со своего аккаунта, то есть сколько угодно: писать владельцу, пересылать и копировать сообщения чата к себе, править и удалять сообщения бота, менять его настройки, перевести webhook на свой адрес до пробуждения;
  - потерять или подменить очередь. После пробуждения архитектор и сессии выполнят подложенное как слова владельца, в том числе с файлами по `file_id` (Mac скачает их своим токеном — это данные, не указания); необратимое — только по кнопке.
- Не может:
  - получить токен, ключи, вход Claude, запись в GitHub — их в облаке нет;
  - сделать хоть что-то, пока Mac бодр: webhook снят, Telegram его не зовёт;
  - удержать бота после пробуждения — Mac снимает webhook (и чужой тоже) и опрашивает сам;
  - дать «да»: нажатия и «да код» из облака не принимаются, карточки шлёт и нажатия получает только Mac.
- Остаётся:
  - во сне он может переписать текст или кнопки уже открытой карточки разрешения. Лечится проверкой видимой кнопки при нажатии или перевыпуском открытых карточек после пробуждения — следующий шаг;
  - сообщения из облака доходят до архитектора без пометки «написано во сне, в 14:07» — дешёвое улучшение на потом;
  - путь — единственная проверка, что апдейт от Telegram; в журналы адресов он попадёт, если включить их у Worker (выключены). Можно добавить `secret_token` webhook — заголовок в журналы адресов не пишется.
- Чужой без доступа к Cloudflare: путь не угадать (256 бит, новый на каждый сон) — 404; без подписи Mac — 401.
- Сессии на Mac ключ Mac из связки не прочтут: шлагбаум закрывает все записи с именем `archi-telegram…`, а не только токен.
- Mac пропал, не попрощавшись (села батарея, сбой): бот молчит до возвращения Mac; Telegram держит апдейты сутки.

**Как включить** (после аккаунта Cloudflare):
1. `bun src/relay-key.ts` — ключ Mac в связку ключей, печатает открытый.
2. Открытый ключ — в `MAC_KEY` в `relay/wrangler.toml`. Выложить: `bunx wrangler deploy` в `relay/` с API-токеном Cloudflare из связки ключей.
3. В `config.json` — `"relay": {"url": "https://archi-relay.<поддомен>.workers.dev"}`, затем `archi restart`.
4. Проверка: закрыть крышку на батарее и написать с iPhone — придёт «Mac спит…». Открыть — ответы по существу.

**Отвергнуто.**
- Токен бота в облаке — против правила: токены только в связке ключей.
- Общий секрет Mac↔Worker (HMAC) — тот же секрет в облаке.
- Локальный HTTP для помощника — порт и секрет ради одного дочернего процесса.
- Держать Mac бодрым с закрытой крышкой — перегрев.

## 19.10.2026 — решение в одно касание и один голос

Сообщения бота читались как машинный текст, ими было неудобно пользоваться, мешали эмодзи. Самое частое касание — запрос разрешения — приходил сырой командой («🔐 X хочет выполнить: ```git push origin main```», «Зачем: Push main to deploy», ✅/❌). Образец — карточки Claude Projects и Cursor: следующее действие словами и кнопка к нему.

**Бриф решения** (`src/brief.ts`, рисует `src/approvals.ts`):
- первая строка жирным — что изменится («Выложить Маяк»), ниже — где («Обновится beacon.example.com»), что именно («Изменится: …», если сессия писала правки по-русски, иначе сколько их), можно ли вернуть;
- совет архитектора с основанием из фактов: автопроверки GitHub (`gh run list --commit`, проверки PR), снимки кандидата от самой сессии, история проекта (файл в git — вернуть можно), поиск ссылок на удаляемый файл, шлагбаум (`policy.ts`) — почему спрашиваем;
- цветом выделена кнопка, к которой склоняется совет; без совета — зелёная «Разрешить» и красная «Отклонить», как раньше;
- команда, файлы, полный список правок, дифф — под «Подробнее» (сворачиваемый блок rich-сообщения);
- третья кнопка там, где показать может только сама сессия: «Сначала покажи» (выкладка без снимков — сессия снимает кандидата и спрашивает снова) и «Сначала объясни» (команда без описания словами — сессия описывает её по-русски и спрашивает снова). Запрос при этом снимается с просьбой, а не с отказом;
- после решения кнопки гаснут на месте: одна погасшая кнопка-подпись «Разрешено в 14:02» (`InlineKeyboardButton.disabled`, Bot API 10.3);
- снимки кандидата — над брифом, кнопки — под ними. Живой снимок «сайт сейчас» к каждой выкладке больше не снимается: к решению он почти ничего не добавлял и занимал браузер на минуту.

**Без модели.** Короткий вызов Haiku через Agent SDK на этом Mac занял 11–25 с (запуск CLI) — дольше, чем стоит ждать кнопку, а пересказ команды моделью — ещё одна дверь для подсказок из чужого текста. Понятная первая строка для непонятной команды получается иначе: «Сначала объясни» возвращает вопрос сессии, она пишет описание по-русски.

**Шлагбаум точнее, не слабее.** Heredoc (`python3 - <<'EOF' … EOF`) считался перезаписью файла «EOF», и простое чтение журнала уходило владельцу на разрешение. Теперь тело heredoc — stdin своей команды: для cat, grep, git и т. п. это данные, для python/node — код (та же проверка, что у `-c`), для оболочки и всего остального — команды, как раньше. `tee` в файл проверяется как `>`.

**Один голос.** Тревоги «сессия упала», «ход оборвался ошибкой API», «ждёт формы MCP», «ждёт решения в окне» идут архитектору (`architect.notify`); владельцу он пишет сам и только если нужны его решение или руки. Упор в лимит из хука не пересылается никому: архитектор упирается в тот же лимит и сам сообщает о нём один раз.

**Вопрос с вариантами — только кнопки.** Варианты больше не повторяются текстом над кнопками, кнопки «Свой ответ» нет: свой вариант — только ответом (свайпом) на сам вопрос; подсказка об этом — одной строкой, пока вопрос открыт. Постороннее сообщение вопрос не закрывает (раньше «кто меня ждёт?» закрывал открытый вопрос): ход архитектора отпускается, кнопки остаются, а ответ кнопкой потом приходит архитектору отдельным сообщением «Ответ владельца на твой вопрос «…»: …». Пояснения к вариантам, если сессия их дала, — под «Подробнее». Команды («стоп», «что у нас», «лимит») сразу после вопроса остаются командами.

**Отказ не обрывает ход.** После «Отклонить» черновик архитектора 20 с показывал «Выполняю команду…», хотя модель уже думала дальше, — ход выглядел зависшим. Теперь сразу после отказа черновик — «Продолжаю без этого», а отказ говорит архитектору: не повторять и не обходить, продолжать без этого действия или одной строкой сказать, чего не сделал, и закончить ход. И вообще: каждый новый шаг модели (её поток начался, прежний инструмент уже отработал) показывает «Думаю…», а не глагол прошлого инструмента. Живая проверка (Opus, max, push в main, «Отклонить»): ход закончился сам через 7 и 19 с одной строкой; прежний код в том же сценарии — 25 с с «Выполняю команду…» в черновике.

**Тон:** писать по-человечески, профессионально и чётко. Бриф и вопрос пишутся как сильный помощник руководителя: одна мысль в строке; что изменится, можно ли вернуть («Прежнюю версию можно вернуть», «Вернуть нельзя: …» вместо «Откат: …»), что советую; служебных имён нет — репозиторий — именем сайта из настроек, вместо служебного имени сессии (claude-e7, номер) — её папка, почтовый сервис — «Gmail», а не «claude_ai_Gmail»; ни команд, ни путей, ни имён программ на виду — только под «Подробнее»; в своих запросах архитектора папка — по имени, а длинная задача сессии — под «Подробнее».

**Раскадровка дня, слепой судья 4/10.** Устоявшие находки и что изменилось:
- Совет к выкладке «не советую: автопроверка не прошла», а через 11 минут конвейер прошёл: судили по чужому прогону. Теперь — только прогоны той версии (коммита), что уходит, и по каждому конвейеру последний; идёт — «лучше дождаться», нет — нейтрально, без «не советую».
- Цветом выделена только кнопка верного совета; без совета обе нейтральные — красная «Отклонить» читалась как тревога.
- «Изменится: 1 правка, подробности ниже» ничего не говорило: что меняется — первой строкой, словами из правок («Выложить «Маяк»: 3 ссылки меню ведут на новые страницы»). Не по-русски — первая строка без них, а не «1 правка». Если git не ответил, бриф про правки молчит, а не пишет «новых правок нет».
- Push в ветку, где все правки уже есть, ничего не меняет — владельца не спрашиваем (проверено git: ветка на GitHub есть, новых правок нет). Push в main спрашиваем всегда, даже пустой.
- В брифе push была папка («Проекты»), а не проект: первая строка запроса в ветку — словами самой сессии («Отправить правки A* в ветку review-1»), ветка — на виду; кто просит — строкой на виду, когда запрос пришёл не в тему самой сессии.

Проверено глазами: стенд — имитация Telegram для iOS (393 pt @3x), сообщения — настоящий вывод `Approvals` через подменённый транспорт Bot API; снимки «до» и «после» и разбор независимым судьёй по картинкам.

## 19.10.2026 — вид и голос: без значков, один вид на «Пульт», сводку и ответы

**Задача.** Ответ архитектора слипался в стену: кружки-эмодзи, курсив от «A* … A*», кнопки обрезаны.

**Стенд:** чат Telegram для iOS в HTML, тёмная и светлая темы, снимки WebKit @3x. Сверен со снимком настоящего iPhone: тот же ответ переносится по тем же словам во всех 14 строках. Экран — 440 pt (Pro Max), текст 17 pt.

**Что узнали о Telegram для iOS:**
- абзацы rich-сообщения он рисует вплотную, пустая строка не видна. Поэтому `richSafe` ставит между абзацами текста строку с неразрывным пробелом — пустую на вид, но не пустую для Markdown;
- `<details><summary>…` без пустых строк вокруг текста — HTML-блок до первой пустой строки: строки слипаются, Markdown внутри не разбирается. `richSafe` ставит пустую строку после `</summary>` и перед `</details>`;
- полоса закрепа показывает начало текста одной строкой; превью (закреп, экран блокировки) берётся из разобранного текста, поэтому «A\*» там — «A*». Раскадровка снимала звёздочку уже после экранирования и показывала «A» — поправлено (на живом Telegram не проверено: в настоящий чат не пишем);
- у правленого сообщения Telegram пишет время отправки («изм. 07:30»), а не правки — поэтому в «Пульте» строка «Обновлено в …».

**Система вида** (слепой судья — отдельная сессия Sonnet, видела только снимки и вкус владельца; пять кругов правок; потом — замысел в DESIGN.md: писать по-человечески, профессионально и чётко; тревоги GitHub не должны пугать, когда сайт работает; паузы сессий бывают намеренными):
- тон — сильный помощник руководителя: одна мысль в строке, обычные слова, что случилось и что это значит; без внутренних имён (префиксы репозиториев, claude-e7, имена прогонов и веток), эмодзи, ярлыков и жирного ради жирного;
- первая строка — прямой ответ: у «Пульта» «2 ждут вашего решения:» (так и видно в полосе закрепа), у сводки «9 сессий, 2 ждут вашего решения:»; число сходится с названными;
- одно состояние и одни имена на весь бот — «Пульт», ответ «что у нас» и архитектор (инструмент overview отдаёт ту же сводку): «ждёт вашего решения» и что именно, «ждёт «принято»», «работает», «на паузе». Не «без дела», не «закончила ход»; кончился лимит Claude — никто не «работает», все на паузе;
- сразу под первой строкой — только решения, по строке: имя жирным и что именно — «**Каталог** — в терминале вопрос: «Отправить Ольге ответ по задаче?», срок завтра» (вопрос сессии или «в терминале открыт запрос разрешения», срок — из её цели); свой вопрос архитектора — сам вопрос, без «Архитектор —» (так и в полосе закрепа);
- красное — только то, что ломает работу сейчас: «Сайт Маяк не открывается: сервер отвечает ошибкой 502», «Потрачено 91% недельного лимита Claude: если кончится, сессии встанут до завтра, 23:00», «На диске Mac осталось 9 ГБ: пора освободить место». Прогоны GitHub (не стартуют, а сайты работают), нагрузка Mac, сессии на паузе — не красное;
- спокойно, без торопления: «Ждут «принято»: «Арена», «Маяк».» — паузы и ожидание «принято» сознательные;
- справка в конце: у «Пульта» — «Работают 2, на паузе 5.», в сводке — имена в кавычках; кто на паузе по лимиту — с причиной; «Все сайты открываются.», лимит недели, «Обновлено в 15:47» (у правленого сообщения Telegram пишет время отправки);
- кнопки в порядке строк, глагол и имя, подпись видна целиком, по одной в ряд: «Ответить: …», «Подготовить приёмку: Маяк» (у всех одна форма: не влезает одна — у всех «Подготовить: …»), «Разобраться с сайтом Маяк», последней — обратимое решение тем же нажатием, что под запросом: «Отправить код в main: Каталог». «Принято» в терминальную сессию из Telegram честно не засчитывается — его ставит сам владелец в сессии;
- реакций-смайликов нет: ответ ушёл — тишина, не ушёл — одна строка почему;
- первая строка, которую видно на экране блокировки, кончается точкой: иначе она сливается со следующей («…лимит Claude Сессии и я стоим»);
- «лимиты?» — сколько потрачено и хватит ли до сброса при нынешнем темпе: «При нынешнем темпе кончится завтра в 17:20, а сброс — завтра в 23:00.»;
- тревога — событие жирным первой строкой с точкой («Сессия «A*» остановилась в 15:05.»), подробности ниже; кнопки по одной в ряд: главное действие первым («Продолжить»), «Последние шаги», «Открыть в Claude». Карточка — имя и что с ней сейчас («Работает с 09:21», «На паузе»), без пересказа задачи; одна на сессию (запуск и круг наблюдателя разом слали вторую — первая висела «Запускается»);
- «Ответить»: «**Анализ отзывов** спрашивает: … Напишите — передам как есть.»; «Последние шаги» — две последние реплики, время своей строкой, без «Жду…» по кругу, служебной переписки и перетащенных в терминал путей;
- ответ хоста сразу за вопросом — без цитаты вопроса.

**Имена сессий** — словами владельца, одно во всех сообщениях: имя от архитектора или /rename → сайт из адреса в цели («Регламенты», а не тема Claude «Правка формы входа») → своя папка («Каталог») → начало цели → подпапка общей папки, где идёт её работа («Проекты/astar» → «A*», а не «Ветка master и опубликованный сайт»; найденная запоминается, чтобы имя не прыгало) → тема Claude. Упор в лимит — из ошибки API в журнале: «на паузе до 15:40: кончился пятичасовой лимит»; лимит сброшен — решают её последние слова.
