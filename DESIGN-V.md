# Вариант «В»: любой человек подключает свой Mac

**Итог.** Человек, который ни разу не видел систему, подключает свой Mac за три минуты. Порядок такой:

1. Пишет в общий бот @sapfirarchitect_bot и нажимает «Подключить мой Mac».
2. Вставляет в Терминал одну команду.
3. Наводит камеру iPhone на QR-код в Терминале и вводит в Telegram четыре цифры с экрана Mac.
4. Создаёт своего бота одной кнопкой Telegram.
5. Пишет «да» в Терминале.

Дальше у него свой бот-архитектор. Бот работает на его Mac под его собственным входом в Claude. Токены руками никто не копирует. Доступа к Mac владельца и данным владельца у человека нет.

Проверено живым прогоном с подставным Telegram: `bun test/e2e-connect.ts`, 17 из 17 проверок. Всё, что человек видит в Telegram и Терминале, снято на стенде «Telegram для iOS».

## 1. Путь человека

| № | Где | Что видит | Что делает |
|---|---|---|---|
| 1 | Общий бот | Описание до «Начать»: «Архитектор — Claude Code на вашем Mac…» | «Начать» |
| 2 | Общий бот | Что это такое, «бот к вашему Mac доступа не получит», «три минуты» | «Подключить мой Mac» |
| 3 | Общий бот | Команда `curl -fsSL https://…/i \| sh`, два шага, «Скопировать команду» и «Что видит этот бот» | Копирует. Буфер обмена у iPhone и Mac общий |
| 4 | Терминал | Проверки: Claude Code (вход выполнен), Bun, код. Затем QR и ссылка | Наводит камеру iPhone |
| 5 | Общий бот | «Mac на связи. Введите код с экрана Mac»; «если вы не запускали команду — ничего не вводите» | Вводит четыре цифры |
| 5а | Общий бот | «Код верный. Теперь создайте своего бота», кнопка под полем ввода | «Создать моего бота» |
| 6 | Окно Telegram | Создание бота: имя и @имя уже заполнены, их можно поправить | «Создать» |
| 7 | Общий бот | «Бот @… создан. Писать ему можете только вы. Подтвердите на Mac» | — |
| 8 | Терминал | «Telegram: Ольга Тестова, @olga_t, бот @olga_t_arch_bot. Подключить? Напишите «да»» | «да» |
| 9 | Терминал | «Подключено», имя бота, автозапуск, команды archi | — |
| 10 | Личный бот | Описание до «Начать»: «Ваш архитектор на Mac… Отвечает только вам» | «Начать» |
| 11 | Личный бот | Приветствие и мастер: где проекты, есть ли сайты, следить ли за GitHub. Всё кнопками | Три ответа |
| 12 | Личный бот | «Настроено», закреплённый «Пульт»; на «что у нас» — сводка | Пишет задачу |

**Почему такой порядок.** Сначала коннектор, потом бот:
- QR-код несёт открытый ключ Mac. Когда создаётся бот, менеджер уже знает, на какой ключ запечатать токен. Этот ключ пришёл с телефона человека через Telegram, мимо ящика.
- Если человек сначала создаст бота, токен будет некуда отправить. Тогда менеджер пришлёт инструкцию, и бот достанется Mac при подключении.

**Код с экрана Mac.** Ссылку `/start c…` из чужого Терминала можно переслать кому угодно, а четыре цифры с экрана своего Mac — только увидеть. Пока код не введён, менеджер ничего необратимого не делает: не создаёт бота и не перевыпускает ключ. Три неверных кода — QR сгорает.

**Повторное подключение** (новый Mac, переустановка): человек снова сканирует QR и вводит код. Только после этого менеджер перевыпускает ключ его бота (`replaceManagedBotToken`), поэтому прежний Mac от бота отключается.

## 2. Managed bots — что есть в Telegram на октябрь 2026

Источник — документация Bot API и её changelog.

- **Bot API 9.6 (03.04.2026).** Бот-менеджер создаёт ботов людям и управляет ими. Из этой версии нужны:
  - `User.can_manage_bots` в `getMe`;
  - кнопка клавиатуры `request_managed_bot` (`KeyboardButtonRequestManagedBot`: `request_id`, `suggested_name`, `suggested_username`; только в личном чате);
  - апдейт `managed_bot` (`ManagedBotUpdated`: кто создал и какой бот) и служебное сообщение `managed_bot_created`;
  - `getManagedBotToken`, `replaceManagedBotToken`;
  - ссылка `https://t.me/newbot/{менеджер}/{имя}?name={название}`.
- **Bot API 10.0 (08.05.2026).** Добавлен `setManagedBotAccessSettings(user_id, is_access_restricted, added_user_ids)`. Менеджер закрывает личного бота для всех, кроме создателя: «The bot's owner can always access it».
- **grammY 1.46** знает всё это: типы, `ctx.managedBot`, методы API.
- **В @BotFather** у общего бота нужно один раз включить **Bot Management Mode**: @BotFather → Open → бот → Bot Settings.
  - Без этого кнопка создания не работает.
  - Хост видит выключенный режим по `getMe.can_manage_bots` и отвечает незнакомцам «Подключение пока закрыто».
- Апдейт `managed_bot` приходит, только если он есть в `allowed_updates`. Хост добавляет его сам, когда включено подключение.
- **Не подтверждено:**
  - как выглядит окно создания бота на iPhone (в стенде нарисовано приближение);
  - сколько ботов разрешено на человека и на менеджера.

## 4. Ящик — протокол

Клиент — `src/box.ts`. Эталонный сервер для проверок — `test/mock-relay.ts`. Настоящий relay (Cloudflare Worker и Durable Object на каждый ящик) строится отдельно и сводится с этим описанием после слияния.

```
POST /v1/box/{id}           положить конверт
  id    — 32 знака base64url = base64url(SHA-256("archi-box-v1:" + ключ_Mac))[0..32)
  тело  — JSON до 8 КБ: {"v":1,"eph":"…43…","iv":"…16…","ct":"…","sig":"…86…"}
  ответ — 201; 413 — больше 8 КБ; 429 — в ящике уже 8 конвертов
GET  /v1/box/{id}?wait=N    забрать конверты (N ≤ 25)
  ответ — 200 {"messages":[…]}: всё, что лежит; если пусто — держит запрос до N секунд
GET  /i, /archi.tgz          раздача (статика): установщик и код
```

- Ни авторизации, ни секретов: что взять из ящика, решает расшифровка и подпись на Mac.
- Конверт живёт 15 минут от первого; в ящике не больше 8 конвертов.
- Серверу стоит ограничить частоту по IP. Удаления нет: ящик истекает сам.

**Криптография.** Только WebCrypto, как у запечатанных конвертов age и libsodium:

- **Ключ Mac** — X25519. Создаётся в `src/connect.ts` и живёт только в памяти этого процесса. В ссылку `/start c<43 знака>` идёт открытая часть: 44 знака при пределе Telegram 64.
- **Запечатывание** у менеджера:
  - одноразовый ключ `eph`;
  - `X25519(eph, ключ_Mac)`;
  - HKDF-SHA256 (соль `eph‖ключ_Mac`, info `archi-box-v1`);
  - AES-256-GCM: случайный iv, AAD `archi-box-v1:{id}`.
  - Общий нулевой секрет (точка малого порядка) отвергается.
- **Подпись** — Ed25519 ключом менеджера над `archi-box-v1:{id}.{eph}.{iv}.{ct}`. Открытый ключ подписи вшит в `install.sh` при сборке раздачи.
- **Письмо** внутри: `{v:1, token, bot{id, username, name}, owner{id, name, username}, manager, at}`.
- **Mac принимает конверт**, только если сходится всё:
  - подпись менеджера;
  - расшифровка;
  - свежесть (не старше 15 минут);
  - имя менеджера;
  - `getMe` по токену возвращает тот же номер бота;
  - человек написал «да», увидев имя и @имя аккаунта. Enter, нажатый заранее, не считается; конец ввода — отказ.

## 5. Коннектор, установка и снятие

- **Установка одной командой:** `curl -fsSL https://<раздача>/i | sh`. Короткий адрес — чтобы команда в сообщении не рвалась посреди слова. Скрипт `bin/install.sh`:
  1. Проверяет Claude Code и вход. Если Claude Code нет — предлагает официальный установщик Anthropic; если нет входа — `claude auth login`, окно Anthropic.
  2. Ставит Bun, если его нет.
  3. Скачивает `archi.tgz`, сверяет SHA-256 и раскладывает код в `~/.archi/app`. Прежние `config.json`, `state` и `logs` сохраняются.
  4. Пишет `config.json` новой установки: служба `app.archi.host`, связка ключей `archi-telegram`, ни сайтов, ни репозиториев, `setupDone: false`.
  5. Подключает Telegram (`src/connect.ts`).
  6. Включает автозапуск через `archi on`, то есть launchd. Ставит общий хук в `~/.claude/settings.json`.
- **QR** рисует штатный CoreImage macOS (`CIQRCodeGenerator` через JXA), без сторонних библиотек. Полублоки, чёрное на белом — читается в любой теме Терминала.
- **Сборка раздачи у владельца:** `bun src/guest.ts dist <папка>`. Получаются `i` (это `bin/install.sh` с вшитыми адресами и ключом) и `archi.tgz`; архив собирается из явного списка файлов, без данных владельца.
- **Снятие одной командой:** `archi uninstall`. Порядок:
  1. Останавливает службу и сессии архитектора (их хуки ведут в удаляемую папку).
  2. Снимает общий хук.
  3. Удаляет из связки ключей токен бота и секрет хуков, удаляет команду `archi`. Ключ подписи менеджера остаётся: им подписаны уже выданные установщики.
  4. Удаляет `~/.archi`.
  5. Подсказывает, что бот в Telegram удаляется в @BotFather.
  - Папку, поставленную не установщиком (у владельца это git-репозиторий), не трогает.

## 6. Чужие в общем боте

Раньше бот молча отбрасывал всё, что приходило не от владельца. Теперь, если подключение включено (`config.connect`), чужое уходит в отдельный путь `src/guest.ts`:

- **Где разделяется.** В первом обработчике Telegram-слоя, до квитанций, до разбора сообщения и до обработчиков кнопок. Обработчики владельца для чужих не вызываются вовсе.
- **Что умеет этот путь:** приветствие, инструкция, «Что видит этот бот», приём QR-ссылки, создание бота.
- **Чего нет:** архитектора, инструментов, сессий, файлов (ничего не скачивается), подтверждений. Отвечает только заранее написанными текстами, слова незнакомца в ответах не повторяются.
- **Журнал:** номер Telegram, вид события («старт», «сообщение», «нажал кнопку»), имя созданного бота. Текст сообщений туда не попадает.
- **Частота:** на человека — 8 в минуту и 60 в сутки; всех чужих вместе — 60 в минуту (это ограничивает и ответы, и записи на диск). Сначала лимит человека, потом общий: один аккаунт не выест общий лимит. Сообщения из групп не считаются. Апдейт о создании бота присылает сам Telegram — его не душит никакой лимит. Сверх лимита — без ответа.
- **Опрос владельца не ждёт:** путь работает без ожидания, медленный ящик не задерживает сообщения владельца. Есть тест.
- **Владелец.** Его архитектор по-прежнему слушает только его. Владелец тоже может подключить ещё один свой Mac — тем же QR.
- **Пока `config.connect` не задан,** поведение бота владельца не меняется: чужие отбрасываются молча.

## 7. Хост для любого человека

**Что стало настройкой.** Привязка к установке владельца из кода убрана:
- `label` — служба launchd;
- `keychainService` и `keychainAccount` — для `archi token`, `status`, `ask`;
- `voice.vocab` — словарь распознавания голоса;
- `browserLock` — общая очередь браузера.

Остальное:
- **Новая установка** начинает с пустых сайтов и репозиториев; правило хостинга не срабатывает, пока его не задали.
- **`CLAUDE.md`** стал общим. Заметки владельца лежат в `CLAUDE.local.md`: архитектор его читает, в раздачу он не входит.
- **`bin/arch`** берёт имена из `config.json` и `state`.

**Установка владельца** не меняется: в его `config.json` эти поля записаны явно (`app.archi.host`, `archi-telegram`, словарь и путь очереди).

**Мастер настройки** (`src/setup.ts`) работает только в установке из установщика. Три вопроса кнопками:
1. Где проекты. Предлагает папки, где уже работал Claude, и обычные места: Рабочий стол, Документы, Developer, Projects. Можно выбрать несколько или всю домашнюю папку.
2. Есть ли сайты. Адреса присылаются текстом.
3. Следить ли за GitHub — если на Mac есть вход в `gh`.

Ответы ложатся в `config.json`. После этого запускаются архитектор и наблюдатель. `/setup` — пройти мастер заново. У установки владельца мастера нет.

| **Менеджер** (Mac владельца или токен общего бота в чужих руках) | Забрать или перевыпустить токен личного бота (так устроены managed bots). Читать новые сообщения человека его боту, писать от имени бота — фишинг. Отключить бота | Управлять Mac человека: хост слушает только сообщения от аккаунта человека из своего опроса, а Bot API не умеет писать «от имени человека». Нажать за человека «Разрешить»: одноразовые коды кнопок приходят только в опрос Mac. Достать вход в Claude, файлы и сессии человека | Честно сказано человеку («Что видит этот бот»). Токен общего бота — в связке ключей владельца |
| **Telegram** | Видеть переписку | — | Данность: ботам нет сквозного шифрования |
| **Утечка токена в журналы** | — | — | `scrub` скрывает всё, что похоже на токен Telegram; свой токен хост ещё и запоминает (`registerSecret`), чужие — нет. E2e проверяет, что токена нет в состоянии и журналах менеджера, в журналах хоста человека, в выводе Терминала и в ящике |
| **Сам человек** | Всё на своём Mac | Обойти свой же шлагбаум | Тот же `policy.ts`: необратимое — его кнопкой. Чтение всех секретов архитектора из связки ключей (токен, хук, ключ менеджера) закрыто для сессий |

**Остаточные риски**

- **Нечестный менеджер.** Может перехватить опрос личного бота: Mac человека перестанет получать сообщения. Потом стоит сделать предупреждение человеку при чужом webhook или конфликте опроса.
- **Скрипт раздачи не подписан.** Решается нотаризацией (раздел 9).
- **Правила Anthropic.** Claude работает у человека под его входом на его Mac: Agent SDK запускает его собственный `claude`, вход мы не видим и не храним. Это не «route requests through … credentials on behalf of their users». Но Agent SDK overview: «Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK». До публичной раздачи нужен ответ Anthropic. Если ответ «нет», два пути:
  - ключ API человека (Agent SDK понимает `ANTHROPIC_API_KEY`);
  - мозг — штатная сессия `claude`.

## 9. Что нужно от владельца

- **@BotFather:** включить Bot Management Mode у @sapfirarchitect_bot (Open → бот → Bot Settings).
- **Адрес:** домен или поддомен для ящика и раздачи (например, `archi.example.com` на Cloudflare Worker); после слияния с relay вписать его в `config.json` → `connect.relay` и `connect.dist`.
- **Раздача:** один раз `bun src/guest.ts dist <папка>` и залить её на этот адрес; повторять после каждого обновления кода.
- **Apple Developer ID** ($99 в год) — по желанию, для подписанного и нотаризованного `.pkg` вместо «curl | sh».
- **Anthropic:** письмо о распространении коннектора на Agent SDK с входом пользователя (раздел 8).
